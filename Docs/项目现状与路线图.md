## 0. 30 秒摘要

UE 5.6 C++ 项目，目标是 **"LLM 指挥 NPC 行为"**（不是"让 NPC 会说话"）。

当前状态：**LLM 对话组件能用、传统 AI（感知→黑板→行为树）能跑，但两者还没有接起来** ——
LLM 组件挂在关卡里的一个立方体（`Cube_Blueprint`）上，猫身上没有大脑。
**所以"LLM 指挥行为"的完成度是 0%。**

下一步唯一的主线是 **M1**：把 LLM 的结构化决策接进黑板，让行为树真的按意图行动。

## 2. 已定决策（含否决项与理由）

**新会话不要重新讨论这些，除非有新证据。**

| 决策 | 结论 | 理由 |
|---|---|---|
| 主线 | **LLM 指挥行为**：意图 → 黑板 → 行为树执行 | 与"让 NPC 说话"区分开；执行层已现成，精力应放在"接缝"上 |
| 架构红线 | **LLM 只写意图到黑板，绝不直接驱动移动/动画** | 1–3 秒的决策延迟不能进每帧循环；降级时必须能退回纯行为树 |
| ❌ 否决：可见性 / shadow map / GPU 深度图 | 不做 | ① 传统 AI 本来就有 LOS，增量小；② 属于图形技能而非 LLM 集成技能；③ 贵（几天~两周）且难演示；④ 商业化 LLM NPC 的"感知"是**社交感知**，与几何可见性无关 |
| ❌ 否决：行为树全量重写成 StateTree | 本期不做 | demo 观感不变、推迟 2–3 周；可留作后期"两种执行层对比"的增量 |
| ❌ 否决：多 agent 协作 / 多 NPC 类型 / 用户研究 / 统计检验 | 不做 | 投递季净亏；作品只需要 demo + 一张量化图 |
| ❌ 否决：投算法 / 研究岗 | 不做 | 无训练经验；该方向深水区是蒸馏 + RL |
| ❌ 否决：接入 Inworld Decisions 等"判定模型" | 不接 | 2026-11-03 调研（[Inworld Decisions 文档](https://docs.inworld.ai/router/decisions)）：它只返回类型化判定（`noul`/`choice`/`score` + 概率），**不产生台词**。若采用则需"判定 + 生成"两次串行调用，延迟与成本翻倍，且新增一个供应商 + key。现有方案（单次调用返回 `{action,speech}` + 本地白名单校验，实测 20/20）已覆盖它唯一的好处（免解析）。**保留其思想**：① 决策与表达分离的理念；② 置信度可作为弱信号（但 LLM 自评置信度不可靠，不能当安全机制）；③ 其 ~200 ms 延迟数据可作为 M2 量化时的对照口径 |
| 动作 = **状态切换**，不是一次性动作 | 定案 | 2026-11-05 试过 goal/mode 双类型（有终点 vs 无终点）+ 完成判定 + watchdog，发现：① LLM 该输出的是**意图/状态**，"开一枪"是执行层的事；② 200 行复杂度全来自这个错误抽象；③ 把状态切换交给 LLM、执行细节留给行为树后，契约收敛成 1 个枚举，代码删掉一半。**不要再用"动作"模型表达 LLM 输出**（除非真的需要一次性的原子动作，如"拾取"） |
| 再进一步：**工具调用 + 观察循环** | 定案 | 状态枚举只解决了"持续行为"，解决不了"先看再走""先 A 后 B"。2026-11-09 引入 ReAct 最小闭环：每轮一个 `tool_call`，结果作为 `[观察]` 回填，最多 3 步。**状态枚举没有消失**——它变成了 `idle/follow/patrol/combat` 这几个工具，行为树仍按 `NPCBehaviour` 执行 |
| 岗位定位 | **UE 客户端 / Gameplay 校招**，外企优先 | 见第 5 节 |

> 一份实验实现 `VisionSamplerComponent`（可见性采样组件）曾写过，**用户要求删除，不要重建。**

## 6. 工作环境的硬约束（都是踩过的坑）

| 约束 | 说明 |
|---|---|
| **沙箱写限制** | agent 的 pwsh 默认**不能写** `Intermediate/`、`Binaries/`、`Saved/`、`.git/`、`%LOCALAPPDATA%`（实测；工作区**根目录**可写）。改文本用文件编辑工具；构建、改 `.git/config`、删构建产物需**用户批准的一次性完全权限** |
| **编译（已打通，但有三个前提）** | agent **可以**跑构建，但必须同时满足：① 用户批准完全权限（要写 `Intermediate/`、`Binaries/`、AppData 日志）；② 编辑器与 Live Coding **完全退出**，否则报 `Unable to build while Live Coding is active`（`Intermediate` 里残留的 `LiveCodingInfo.json` **不影响**，已实测）；③ 见下一行的中文路径坑 |
| **构建中文路径坑** | git 默认 `core.quotepath=true` 把中文路径输出成 `\351\241…` 转义，UBT 的 `GitSourceFileWorkingSet` 将其当路径分隔符而**整进程崩溃**（`-532462766` / `ArgumentException`）。本仓库已用 `git config --local core.quotepath false` 修掉；**换机器/重建仓库会复现** |
| **LLM 上下文的格式自洽** | `response_format=json_object` 要求历史里的 assistant 也是 JSON。若历史存的是**纯台词**，模型会退化成一味输出空白字符（实测 17/20：`finish=stop`、`ctok>0`、`content` 全空白）。**契约：历史存原始 JSON，屏幕显示 Speech，两者分离。** 复现工具 `Tools/deepseek_probe.py`（不经 UE，4 种历史策略各 20 条） |
| **蓝图枚举按显示名匹配** | Blackboard 的枚举键通常是**蓝图枚举**（UserDefinedEnum），内部条目名是 `NewEnumerator0/1`，`Patrol` 只是显示名。`UEnum::GetValueByName("X::Patrol")` 会失败 —— 要遍历 `GetDisplayNameTextByIndex` / `GetNameStringByIndex` 两者都比，失败时把可用名字打出来 |
| **行为树顶层只有一个门** | 以前先后用过 `IsPlayerInSight`、`bShouldFollow` 做顶部门，都导致"同一个意图被两个键表达"。**最终方案**：顶层只按 `NPCBehaviour` 分支，其余键都是事实/参数。加状态 = 枚举加值 + 加一个分支 |
| **只有一个"到达半径"** | 控制器上曾有一个 `ArriveRadius`（LLM 目标完成半径），与行为树 `Move To` 的 `Acceptable Radius` 并存，容易互相打架。**现已删除**，只剩 BT 节点上的 `Acceptable Radius`（走路任务自己的判定） |
| **玩家 Pawn 本身就是 `BP_SteampunkCat`** | 关卡 GameMode 的默认 Pawn 是 Sabertooth 的猫，所以两只 NPC 的 `ChasingTarget` 里出现"一只猫"是**正常的**——那就是玩家。录像前若想让叙事更清楚（人 + 机械猫），需要换 DefaultPawnClass，属于待定项 |
| PowerShell 是 **5.1** | 无 BOM 的 `.ps1` 会按 GBK 解析中文（已踩）→ 脚本须存 UTF-8 **with BOM**；读写 UTF-8 文件要显式 `-Encoding UTF8` |
| UE 5.6 API 事实 | `UWorld::GetTimeSeconds()` 返回 **`double`**；`FConfigCacheIni::LoadFile()` 返回 **`void`**（四参 `GetString` 才返回 bool）；`AActor::GetActorBounds(bool, FVector&, FVector&, bool)`；**`FAutoConsoleCommandWithArgs` 已不存在** —— 用 `FAutoConsoleCommand(Name, Help, FConsoleCommandWithArgsDelegate, Flags)`（`HAL/IConsoleManager.h` 第 2011 行那个重载） |
| 第三方资产 | `Content/` 大部分是 Epic `Factory_LP` + 商店 `Sabertooth`。**公开仓库再分发通常违反 EULA**；README 必须写"我写的 vs 第三方" |
| 读取禁区 | `Intermediate/` `Binaries/` `Saved/` `.vs/` 等 —— 详见 `CLAUDE.md` 的 Read scope |

## 7. 背景知识（已核实的对外事实，避免重复调研）

- **论文**：[arXiv 2604.19192v2](https://arxiv.org/abs/2604.19192v2)（Radež & Bohak，卢布尔雅那大学，
  2026-04，CC BY 4.0）*Empowering NPC Dialogue with Environmental Context Using LLMs and Panoramic
  Images*。做法：UE5 + Blueprint、GPT-4 API、**构建期**拍 4×90° 全景、RAM++ 分割成"方向桶"JSON、
  bounding sphere 列物体 + 方向向量；**坐标变换写在 prompt 里让 LLM 翻左右**；**无遮挡、无移动目标、
  无运行时感知**。评估：专家访谈 + 58 份问卷。
- **商业对照**：米哈游《星布谷地》AI 总负责人李嫣然 2026 云栖大会演讲 —— 一套 Agent 架构
  （决策中枢仿前额叶 → 行动层）、"超智记忆系统"（角色间共享 / 跨平台 / 跨测试保留）、一对一vs一对多
  控场、多教师在线蒸馏、混合奖励含**安全底线**；明确提到"时延与成本"。**他们的"感知"是社交感知。**
- 燕云十六声的自由对话 NPC 被玩家用话术骗过（AUTOMATON 报道）→ 这类功能上线后的真实痛点是
  **安全、舆论与合规**，不是感知精度。
- **结论**："LLM 指挥行为"**不是空白**（SayCan / Voyager / Ubisoft NEO NPC / NVIDIA ACE 已覆盖），
  所以差异化只能来自 **工程闭环 + 量化 + 能辩护的取舍**，不能靠"novelty"。

1. **先别写代码。** 用户明确要求：计划确认前不要动手。曾因未经同意写 400 行代码被要求删除。
2. **逐条批准。** 他按编号批（"1、2、3 做"或"全批"），**只做批过的条目**。
3. **每条先给验证方法**，他验完再进下一条。
4. **不要自己扩大范围**；**不要把他否决的方向重新提出来**（见第 2 节）。
5. 说话直接、承认错误。之前两处判断失误（"实习优先"、误判代码可编译）已被纠正，别重复。
6. **不要主动提交 GitHub。** 除非当轮明确说"提交/推送"，否则不执行 `git commit` / `git push`：
   改完留在工作区，报告"已就绪"，由他决定何时提交。`git add` 只在已批准的提交里用。
   （2026-10-28 明确要求。）
