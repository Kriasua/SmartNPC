# SmartNPC 项目规划与求职路线

> 本文档是 SmartNPC 项目的总纲:它要做成什么、为什么这么做、分几步做、每一步对应什么求职竞争力。
> 技术实现细节见 `Docs/AIBrainComponent详解.md`;源码为准。

---

## 0. 一句话定位

**做一个"有记忆、有性格、会跟随玩家并能和其他 NPC 协作"的伙伴型 LLM-Agent NPC**,
用传统游戏 AI(状态树/行为树 + 寻路 + 感知)当身体,用 LLM 当大脑,
最终成为一个能精准命中"游戏 AI 工程师"岗位、同时能背书 UE C++ 工程能力的作品集核心。

---

## 1. 求职目标与个人定位

### 主线目标:游戏 AI 工程师 / Gameplay AI Engineer(引擎侧)
把 LLM Agent 落地进 UE、做工具链、做性能优化。**这是本项目的主战场。**

和现有技能不匹配。不投入。

- C++ 基础扎实、数据结构与算法掌握牢固 → **可跳过补基础,直接攻工程深度与系统设计**
- 无 PyTorch / ML 训练经验 → 不走算法路线

## 2. 核心设计理念

### 2.1 LLM 只在"开放式决策"时才有价值
LLM 又慢(数百 ms~数秒)、又花钱、偶尔不稳定。**凡是能用按键/行为树解决的,就不该用 LLM。**
LLM 的唯一价值:处理"无法提前写成 if-else 的开放输入"——比如玩家用自然语言下达的模糊指令。

### 2.2 两层架构:LLM 当指挥官,传统 AI 当士兵
```
┌─────────────────────────────────────────────┐
│  LLM 大脑(慢,偶尔思考一次,事件驱动)          │
│  高层决策:追玩家? 去捡箱子? 说什么话?        │
│  输出 → 一个高层"状态/目标/动作指令"            │
└───────────────────┬─────────────────────────┘
                    │ 写入 Blackboard
                    ▼
┌─────────────────────────────────────────────┐
│  状态树 / 行为树(快,每帧执行,稳定可控)        │
│  底层执行:寻路、避障、播动画、到了没、卡住重试   │
└─────────────────────────────────────────────┘
```
**"把这两层接起来"本身,就是岗位 JD 里"结合传统游戏 AI 与生成式 AI"的核心能力,也是最值钱的卖点。**

### 2.3 执行层技术选型:状态树为主,行为树概念必备
- **状态树(StateTree)**:本项目执行层用它落地。更现代、Epic 主推、且"LLM 切高层状态"与状态树模型天然契合。
- **行为树(Behavior Tree)**:行业通用语言、面试高频考点。**概念必须懂**(Selector/Sequence/Task/Decorator/Service/Blackboard),但不必做深。
- 面试话术:"两个都懂,本项目特意选状态树,因为 LLM 做的就是切高层状态,与 StateTree 状态模型契合。"

## 3. 技术路线:五个阶段

每个阶段都能独立展示、都对应明确的 JD 得分点。**深度优先,不贪多。**

### 阶段 1 — chatbot → agent(地基)
**目标:** 让 NPC 从"只会回文本"变成"会输出动作决策"。
**改动集中在 `AIBrainComponent.cpp` 的 JSON 构建 / 解析两段,Blueprint 接口与 UPROPERTY 不动。**

- [ ] 加 system prompt(告诉 LLM:你是游戏 NPC,必须回 JSON,可选动作 chase/move_to/follow/say/idle)
- [ ] 请求构建:把 system prompt 插到 `ConversationMessages` 最前
- [ ] 响应解析:不再当纯文本广播,解析出 `action` + `speech` + 参数
- [ ] 新增 Blueprint 委托(如 `OnNPCDecision`),把"决策"交给蓝图/执行层
- [ ] 蓝图/C++ 侧:`action == chase/follow` → MoveTo;`speech` 非空 → 头顶显示对话

**对应 JD:** ① Agent 架构 + LLM 与玩法融合
**演示效果:** 玩家说话 → NPC 自己决定追/走/说,而不是固定回复。

---

### 阶段 2 — 注入灵魂:记忆 + 性格
**目标:** NPC 记得你、有稳定人格、情绪会变。这是"颠覆脚本化"的核心。

- [ ] 性格/情绪 system prompt(可配置的人格设定)
- [ ] **持久化记忆**:`ConversationMessages` 现在是纯内存,要存盘(SaveGame / JSON 落地),关游戏不丢
- [ ] **长期记忆**:对话历史做摘要压缩,避免 token 爆炸;关键事件单独存(玩家做过什么)
- [ ] **RAG / 向量检索记忆**(关键加分):用向量库存记忆,按当前情境检索相关记忆喂给 LLM
      → 这一块同时出现在算法岗 JD 里,且不需要训练模型,性价比最高的"留钩子"
- [ ] 情绪状态机:好感度/警惕度等数值,影响 system prompt 与行为

**对应 JD:** ② 记忆、情感、动态决策
**演示效果(杀手锏):** 让伙伴原地等,你去打架,回来它说"你刚才差点死了我都看见了,下次带上我"——它真的记得。

---

### 阶段 3 — 多智能体(让世界活起来)
**目标:** 两个 NPC 能感知彼此、互相对话/协作/传递信息。

- [ ] NPC 之间的感知(AI Perception:看见/听见彼此)
- [ ] NPC 间对话机制(一个 NPC 的输出成为另一个的输入)
- [ ] 简单协作 / 信息传播(A 知道的事会传给 B)
- [ ] 防止无限对话循环、token 失控的控制机制

**对应 JD:** ③ 多智能体协同 + "活"世界
**演示效果:** 面试最炸的片段——两个 NPC 自然交流、世界随玩家行为演化。

---

### 阶段 4 — 工具链(赋能非技术人员)
**目标:** 策划/非程序员填表就能造出新性格的 NPC,不碰代码。

- [ ] 用 DataTable 配置 NPC 性格/初始记忆/可用动作
- [ ] (进阶)自定义编辑器面板 / 数据驱动
- [ ] 运行时热重载性格配置便于调试

**对应 JD:** ④ 工具链让非技术人员调教 NPC
**额外价值:** 工具开发能力对**客户端岗也是强加分**(两个方向公约数,优先做)。

---

### 阶段 5 — 性能优化(玩具 → 产品)
**目标:** 几十个有大脑的 NPC 同屏不卡。这是区分"demo"和"工程"的分水岭。

- [ ] LLM 请求异步队列 + 并发上限控制
- [ ] 调用节流(事件驱动,绝不每帧调)
- [ ] 相同情境结果缓存
- [ ] **思考频率 LOD**:远处/不重要的 NPC 降低思考频率甚至休眠
- [ ] Profiling:用 UE 工具量化 CPU/帧时间/请求延迟
- [ ] (可选)Agent Eval:自动化评测 NPC 决策质量/角色一致性(同时蹭算法岗关键词)

**对应 JD:** ⑤ 海量 AI 运算下的极致优化
**额外价值:** 性能优化对**客户端岗是核心竞争力**(两个方向公约数,优先做)。

## 4. 需要学习的传统 AI 知识(够用即止)

**必学:**
- 行为树概念:Selector / Sequence / Task / Decorator / Service / Blackboard(面试通用语言)
- 状态树:本项目执行层(实战)
- Blackboard:LLM 与执行层之间的数据桥梁
- 自写 BTTask / StateTree Task:执行 LLM 给的指令
- AI Perception(感知系统):NPC 怎么"看见/听见",喂给 LLM 当输入
- NavMesh / Nav Link Proxy:寻路(已掌握基础)

**可暂时跳过:**
- GOAP / Utility AI(决策层已是 LLM,用不上)
- 复杂战术 EQS、大规模群体行为(偏纯战斗 AI,非本项目主线)

## 5. 两个方向的作品定位

| | 游戏 AI 工程岗(主线) | 游戏客户端岗(备选) |
|---|---|---|
| 怎么讲这个项目 | LLM-Agent 架构、记忆/多体/性能 | 有深度的 UE C++ 工程样本 |
| 突出什么 | LLM 与传统 AI 的"结合"能力 | 异步/线程安全/组件设计/蓝图接口/工具链/性能 |
| 还需补什么 | 无(项目即主答卷) | CS 八股(已扎实)+ 系统广度(UI/网络同步小 demo) |
| 公约数(都加分) | 阶段4工具链、阶段5性能优化 ← **优先做** | 同左 |

项目里已体现的可迁移 UE C++ 能力(看 `AIBrainComponent`):
组件生命周期、异步 HTTP、线程 marshal(`BroadcastOnGameThread`)、JSON 序列化、
动态多播委托、C++/蓝图交互、EndPlay 资源清理与防悬空(`TWeakObjectPtr`)。

## 6. 作品集叙事(面试时怎么讲)

JD 反复强调**玩家同理心、体验、不局限于代码**。所以技术之外,要能讲清楚:
**"为什么这样设计能让玩家觉得 NPC '活'了。"**

讲述结构建议:
1. **问题**:脚本化 NPC 的体验天花板在哪。
2. **设计**:为什么选伙伴型 + 两层架构(LLM 决策 + 状态树执行)。
3. **杀手锏 demo**:那个"NPC 记得你、像活着"的瞬间。
4. **工程深度**:记忆持久化 / RAG、多智能体控制、性能 LOD —— 怎么从玩具做成能跑几十个的系统。
5. **取舍**:哪里用了 LLM、哪里坚决不用,以及为什么(体现工程判断力)。

## 8. 执行原则

1. **深度 >> 广度**:一个打磨到位的系统,碾压四个半成品。
2. **每阶段产出可独立演示的成果**,随时能拿去面试。
3. **公约数优先**(阶段4工具链 + 阶段5性能):同时服务两个求职方向。
4. **改动遵循 CLAUDE.md 约定**:`generated.h` 最后引入、UE 智能指针、异步用 `TWeakObjectPtr`、EndPlay 清理。
5. **源码与 `Docs/AIBrainComponent详解.md` 同步更新**,源码为准。
